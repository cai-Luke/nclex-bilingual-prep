## Findings and exact repair

The independent checker findings supplied by the owner report no production-code defect and a reproduced true baseline red. They identify two defects in the earlier producer harness: a live reference app could overwrite newly seeded state from the preceding condition, producing opposite language mismatches across runs; and the runner admitted references without asserting submission-state identity, including observed `submitted: true` under requested `submitted: false` conditions. The earlier producer-green evidence therefore does not establish acceptance under the corrected harness.

Only `scripts/tests/mobile-dropdown-cloze-layout.mjs` changed outside this new evidence directory:

1. Each uncached `matchedNonCloze()` condition gets a fresh temporary Chrome profile/context. The actual app initializes its database; that bootstrap page is then closed, and the runner asserts that no live page remains. A new page at the exact target URL is served inert HTML by a task-only route. After asserting the seed page has no scripts/app shell, the runner seeds settings/session, removes the route and loads the actual app. Thus no app instance capable of persisting old active-session state is alive during seeding. This works with ordinary security for both HTTP and `file://`.
2. Before admission/cache insertion, the runner checks the observed viewport, DPR, theme, text size, language, **`result.submitted === condition.submitted`**, transport and non-overflowing root. Failed identity evidence is retained with `admitted: false`; it cannot enter the cache. The cache contains only validated measurement data. Every context is closed and its profile removed after measurement.
3. Every used reference records requested and observed state, including submission state and root geometry. Every causal ancestor comparison additionally records its requesting cloze state/subject, both ancestor excesses and their delta. [Matched-witness index](matched-witness-index.json) points to complete records in each run's `results.json`.

No sleeps, retries, assertion reordering to mask failure, or acceptance of whichever state happens to appear were added. The causal containment assertions were not weakened. [Scope proof](scope-proof.json), generated by [verify-repair-scope.mjs](verify-repair-scope.mjs), uses the TypeScript AST to show that removing only the new comparison-record statement leaves `containment()` byte-identical to its pre-checker version. All other measurement, scenario, fixture-identity, interaction and readout functions are byte-identical. No generic `.session-shell` exemption exists.
